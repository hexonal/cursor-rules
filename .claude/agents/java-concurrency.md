## 线程池设计指导原则

### 线程池类型选择策略
- **CPU 密集型任务**: 线程数 = CPU 核心数 + 1，避免过多线程切换
- **IO 密集型任务**: 线程数 = CPU 核心数 * 2~4，根据 IO 等待时间调整
- **混合型任务**: 根据任务比例分离到不同线程池处理
- **定时任务**: 使用 ScheduledThreadPoolExecutor，设置合适的核心线程数

### 线程池参数配置原则
- **核心线程数**: 根据系统负载和资源容量设定基础线程数
- **最大线程数**: 设定系统能承受的最大并发数，防止资源耗尽
- **队列选择**: SynchronousQueue（直接提交）、LinkedBlockingQueue（无界队列）、ArrayBlockingQueue（有界队列）
- **拒绝策略**: CallerRunsPolicy（调用者执行）、AbortPolicy（抛异常）、DiscardPolicy（静默丢弃）
- **线程存活时间**: 非核心线程的空闲存活时间，平衡资源使用和响应性

### 异步任务处理模式
- **Fire-and-Forget**: 提交任务后不关心结果，适用于日志记录、通知发送
- **Future 模式**: 异步获取任务结果，支持超时和取消操作
- **Callback 模式**: 任务完成后回调处理，避免阻塞等待
- **CompletableFuture 链式处理**: 构建复杂的异步处理管道

## 同步机制选择指导

### synchronized vs ReentrantLock
- **synchronized**: 简单易用，JVM 层面优化，适用于简单同步场景
- **ReentrantLock**: 功能更丰富，支持公平锁、条件变量、可中断，适用于复杂同步需求

### 读写锁应用场景
- **读多写少**: 使用 ReadWriteLock 提升并发读性能
- **缓存场景**: 读操作不加锁，写操作加写锁并清理缓存
- **配置管理**: 配置读取高频，更新低频的场景

### 其他同步原语选择
- **CountDownLatch**: 等待多个任务完成，典型的并发初始化场景
- **CyclicBarrier**: 多线程协调到达同一同步点
- **Semaphore**: 控制并发访问的资源数量，如连接池、限流

## 并发容器选择策略

### Map 类型选择
- **ConcurrentHashMap**: 高并发读写，分段锁机制，适用于缓存场景
- **ConcurrentSkipListMap**: 有序并发 Map，适用于需要排序的并发场景

### List 类型选择
- **CopyOnWriteArrayList**: 读多写少场景，写操作成本高但读操作无锁
- **Collections.synchronizedList**: 简单同步包装，性能较差，不推荐高并发使用

### Queue 类型选择
- **LinkedBlockingQueue**: 无界或有界队列，生产者-消费者模式
- **ArrayBlockingQueue**: 有界队列，支持公平性设置
- **PriorityBlockingQueue**: 优先级队列，任务按优先级处理
- **DelayQueue**: 延时队列，定时任务处理

## 并发问题诊断与解决

### 常见并发问题模式
- **死锁**: 循环等待资源，通过资源排序、超时机制预防
- **活锁**: 线程持续重试但无法进展，需要随机化重试策略
- **饥饿**: 低优先级线程无法获得资源，使用公平锁或优先级调度
- **竞态条件**: 多线程访问共享资源的时序问题，通过同步机制解决

### 性能瓶颈识别
- **锁竞争**: 通过减少锁范围、锁分离、无锁设计优化
- **线程切换开销**: 调整线程数量，使用批处理减少切换
- **内存可见性**: 合理使用 volatile，避免过度同步
- **伪共享**: CPU 缓存行冲突，通过内存布局优化解决

- **数据并行**: 大数据集的并行处理，如数组求和、排序
- **树形结构遍历**: 文件系统遍历、DOM 树处理

### 任务拆分策略
- **阈值设定**: 设定合适的任务拆分阈值，避免过度拆分
- **工作窃取**: 利用框架的工作窃取机制平衡负载
- **任务类型选择**: RecursiveTask（有返回值）vs RecursiveAction（无返回值）

## CompletableFuture 异步编程指导

### 异步链式操作设计
- **thenApply**: 同步转换结果，CPU 密集型操作
- **thenApplyAsync**: 异步转换结果，IO 密集型操作
- **thenCompose**: 扁平化异步操作链，避免嵌套
- **thenCombine**: 合并多个异步结果

### 错误处理策略
- **exceptionally**: 异常时提供默认值
- **handle**: 同时处理正常结果和异常
- **whenComplete**: 完成时的清理操作

### 超时和取消机制
- **orTimeout**: 设置操作超时时间
- **completeOnTimeout**: 超时时提供默认值
- **cancel**: 主动取消异步操作

### 监控指标设计
- **线程池状态**: 核心线程数、活跃线程数、队列大小、拒绝任务数
- **任务执行指标**: 任务提交速率、完成速率、平均执行时间
- **资源使用情况**: CPU 使用率、内存使用、GC 频率

### 死锁检测与预防
- **JVM 工具**: 使用 jstack、JConsole、VisualVM 检测死锁
- **预防机制**: 资源排序获取、超时机制、死锁检测算法
- **编码规范**: 减少锁嵌套、缩短持锁时间

### 性能调优策略
- **线程池调优**: 动态调整池大小、队列容量
- **GC 优化**: 减少对象创建、使用对象池
- **CPU 亲和性**: 绑定线程到特定 CPU 核心

## 并发最佳实践

### 设计原则
- **无锁优先**: 优先考虑无锁数据结构和算法
- **锁粒度最小化**: 只保护必要的临界区
- **避免锁嵌套**: 减少死锁风险
- **线程局部化**: 优先使用 ThreadLocal 避免共享

### 编码规范
- **资源管理**: 使用 try-with-resources 管理锁资源
- **异常处理**: 确保锁在异常情况下能被正确释放
- **可见性保证**: 正确使用 volatile 和同步机制
- **原子性保证**: 使用原子类或同步机制保护复合操作

### 测试策略
- **并发测试**: 使用多线程压力测试验证并发安全性
- **边界测试**: 测试高并发、资源耗尽等极限场景
- **性能测试**: 验证并发优化的效果
- **死锁测试**: 构造死锁场景验证预防机制
